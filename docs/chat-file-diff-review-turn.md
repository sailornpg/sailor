# Turn 级文件变更审查设计变更

## 背景

现有文件变更日志按 chat 聚合。这样可以查看一个会话的累计变化，但无法直接回答“这一轮回答改了什么”，也会让之前轮次的文件变化出现在当前操作入口中。Codex 风格的交互应把文件变更卡片放在产生变更的 assistant turn 之后，并在 turn 完成时冻结内容。

## 目标

- 将一次用户提交到 assistant 终态定义为一个 `turn`。
- 在 turn 结束后，仅当该 turn 存在净文件变化时，在对应 assistant 消息末尾展示文件变更卡片。
- 卡片展示文件数、增删行数和文件列表；点击审查进入只读 ReviewPanel，并默认过滤到该 turn。
- 保留会话级历史查询作为辅助能力，不让会话累计汇总替代当前 turn 视图。
- 将文件变更卡片、滚动到底部按钮和 composer 组织为上下布局，避免浮层重叠。

## 生命周期与标识

`turnId` 是一次用户提交的稳定标识；`runId` 是该 turn 的一次执行尝试。审批等待、自动重试和恢复执行继续使用同一个 `turnId`。turn 在 `completed`、`stopped` 或 `error` 终态冻结，冻结前已经成功写入的文件操作仍进入本轮净 diff。

每个文件在一个 turn 内以首次修改前快照和 turn 结束时快照计算净差异。文件修改后又恢复原样时，本轮不展示该文件。外部编辑造成的断点标记为 `stale`，不跨断点合并为可靠 diff。

## UI

- 执行中：不展示文件产物卡片；composer 继续显示既有运行状态和审批交互。
- turn 结束：assistant 消息下方显示“已编辑 N 个文件”和 `+added -removed`，并列出文件路径；卡片支持收起文件列表。
- 点击“审查”：打开 ReviewPanel，选择当前 turn 的文件列表和只读 CodeDiff。
- 新 turn 开始后，composer 入口切换到新 turn；旧卡片保留在历史消息中。
- 文件日志刷新期间保留已经加载的旧 summary；只有首次加载且尚无 summary 时隐藏卡片，避免新 turn 写入时历史卡片闪退。
- 没有净文件变化的 turn 不展示卡片。
- 本 feature 不实现撤销、应用或写回操作。

## 布局约束

滚动到底部按钮属于 viewport footer 的导航控件，文件变更提示属于消息内容，两者不得使用同一位置的绝对定位。footer 内采用垂直布局：滚动按钮位于上方，composer 位于下方；消息卡片在 assistant 消息流内占据正常文档流高度，并与 composer 保持底部间距。亮色、暗色和窄窗口下都必须无重叠、无横向溢出。
流式生成时默认跟随底部；用户通过滚轮、触控或滚动条向上移动后暂停自动跟随，回到底部后恢复。viewport 不使用持续的 CSS 平滑滚动，避免每个 token 的尺寸变化与手动滚动争抢位置。

## 数据与 IPC

日志记录保存 `chatId`、`turnId` 和 `runId`。新增按 `turnId` 查询 summary/detail 的窄 IPC；chat 级 summary 继续用于历史汇总和兼容已有入口。renderer 不提供可执行路径，也不参与文件快照计算。

## 验收

- 连续两个 turn 修改同一文件时，每张卡片只显示各自 turn 的净变化。
- 审批或重试不会拆分卡片；停止和错误状态仍能查看已发生的变化。
- 历史卡片点击后 ReviewPanel 定位到对应 turn，且审查操作不写文件。
- 文件变更提示和滚动到底部按钮上下排列，点击和键盘焦点不互相遮挡。
- 下一轮生成期间上一轮卡片仍可见，且用户向上滚动后 viewport 不被自动拉回或闪烁。
